# 🧠 Clase: Ejemplos Detallados de Historias de Usuario

## 🎯 Objetivo
El estudiante aprenderá a **redactar, analizar y evaluar historias de usuario completas**, incluyendo su contexto, criterios de aceptación y valor para el negocio.

---

## 📘 Recordatorio: Formato Estándar

> **Como** [tipo de usuario]  
> **quiero** [una funcionalidad o acción]  
> **para** [obtener un beneficio o resultado].

---

## 💡 Ejemplo 1: Plataforma educativa (Moodle)

**Historia de usuario:**  
> Como estudiante, quiero ver mis calificaciones en línea para saber cómo voy avanzando en el curso.

**Criterios de aceptación:**
1. El sistema muestra una tabla con calificaciones por actividad.  
2. El estudiante solo puede ver sus propias notas.  
3. Las calificaciones deben actualizarse automáticamente al ser publicadas por el docente.

**Tipo de usuario:** Estudiante  
**Prioridad:** Alta  
**Valor:** Permite conocer su rendimiento sin depender del docente.

---

## 💬 Ejemplo 2: Aplicación bancaria móvil

**Historia de usuario:**  
> Como cliente del banco, quiero transferir dinero entre mis cuentas para gestionar mis fondos fácilmente.

**Criterios de aceptación:**
1. Solo se permiten transferencias entre cuentas del mismo titular.  
2. El sistema debe confirmar la transacción antes de ejecutarla.  
3. La transferencia debe reflejarse de inmediato en el saldo.

**Tipo de usuario:** Cliente  
**Prioridad:** Muy alta  
**Valor:** Aumenta la autonomía y rapidez del usuario.

---

## 🧾 Ejemplo 3: Sistema de facturación

**Historia de usuario:**  
> Como administrador del sistema, quiero generar reportes de ventas mensuales para analizar el desempeño del negocio.

**Criterios de aceptación:**
1. El reporte debe incluir total de ventas, clientes y productos más vendidos.  
2. El sistema debe permitir exportar a PDF y Excel.  
3. El reporte solo puede generarse para meses cerrados.

**Tipo de usuario:** Administrador  
**Prioridad:** Media  
**Valor:** Permite tomar decisiones basadas en datos.

---

## 🧑‍💼 Ejemplo 4: Portal de empleo

**Historia de usuario:**  
> Como reclutador, quiero filtrar candidatos por experiencia y habilidades para encontrar más rápido los perfiles adecuados.

**Criterios de aceptación:**
1. El sistema permite filtrar por años de experiencia, país y tecnología.  
2. Los resultados deben ordenarse por relevancia.  
3. El reclutador puede guardar búsquedas frecuentes.

**Tipo de usuario:** Reclutador  
**Prioridad:** Alta  
**Valor:** Acelera el proceso de selección.

---

## 🧘 Ejemplo 5: Aplicación de salud y bienestar

**Historia de usuario:**  
> Como usuario de la app, quiero registrar mis horas de sueño para hacer seguimiento a mis hábitos de descanso.

**Criterios de aceptación:**
1. Debe permitir registrar la hora de inicio y fin del sueño.  
2. Mostrar el promedio semanal de horas dormidas.  
3. Permitir editar registros anteriores.

**Tipo de usuario:** Usuario final  
**Prioridad:** Media  
**Valor:** Fomenta hábitos saludables mediante la autoevaluación.

---

## 🛒 Ejemplo 6: Tienda en línea

**Historia de usuario:**  
> Como cliente, quiero agregar productos a mi carrito de compras para comprarlos después.

**Criterios de aceptación:**
1. El carrito guarda productos incluso si el usuario cierra sesión.  
2. Se muestra el total actualizado al agregar o eliminar productos.  
3. Al realizar la compra, los productos se descuentan del inventario.

**Tipo de usuario:** Cliente  
**Prioridad:** Alta  
**Valor:** Mejora la experiencia de compra y fidelización del cliente.

---

## 🧑‍🏫 Ejemplo 7: Sistema académico docente

**Historia de usuario:**  
> Como docente, quiero subir las calificaciones de mis estudiantes en formato CSV para ahorrar tiempo.

**Criterios de aceptación:**
1. El archivo CSV debe tener validaciones automáticas (formato correcto).  
2. Mostrar una vista previa antes de guardar.  
3. Permitir corregir errores detectados.  

**Tipo de usuario:** Docente  
**Prioridad:** Alta  
**Valor:** Reduce el tiempo de gestión de calificaciones.

---

## 📱 Ejemplo 8: Aplicación de mensajería

**Historia de usuario:**  
> Como usuario, quiero poder eliminar mensajes enviados por error para mantener mis conversaciones limpias.

**Criterios de aceptación:**
1. Solo se puede eliminar un mensaje en los primeros 5 minutos después del envío.  
2. Debe mostrar un aviso de “Mensaje eliminado”.  
3. No debe afectar la estabilidad del chat.

**Tipo de usuario:** Usuario final  
**Prioridad:** Alta  
**Valor:** Da control al usuario sobre su contenido.

---

## 💳 Ejemplo 9: App de transporte (tipo Uber)

**Historia de usuario:**  
> Como pasajero, quiero ver el costo estimado del viaje antes de confirmarlo para decidir si lo tomo.

**Criterios de aceptación:**
1. El sistema calcula el costo según distancia y tiempo estimado.  
2. Debe mostrar un rango de precios.  
3. El costo no puede variar más del 20% del estimado final.

**Tipo de usuario:** Pasajero  
**Prioridad:** Alta  
**Valor:** Aumenta la transparencia y confianza del usuario.

---

## 🧑‍💻 Ejemplo 10: Sistema de soporte técnico

**Historia de usuario:**  
> Como técnico de soporte, quiero registrar las incidencias de los usuarios para darles seguimiento hasta su solución.

**Criterios de aceptación:**
1. Cada incidencia debe tener un número único de ticket.  
2. El sistema permite actualizar el estado (pendiente, en proceso, resuelto).  
3. El cliente recibe notificación por correo al cambiar el estado.

**Tipo de usuario:** Técnico de soporte  
**Prioridad:** Alta  
**Valor:** Mejora la trazabilidad y atención al cliente.

## 🧠 Actividad práctica

Crea **3 historias de usuario propias** inspiradas en una app o sistema que uses todos los días.  
Incluye:
- El tipo de usuario  
- La historia con formato estándar  
- Tres criterios de aceptación  
- Nivel de prioridad  

---

## 📝 Rúbrica de evaluación (sugerida)

| Criterio | Excelente (3 pts) | Aceptable (2 pts) | Mejorable (1 pt) |
|-----------|------------------|------------------|------------------|
| Claridad | La historia es clara, comprensible y coherente. | Tiene algunos detalles confusos. | No se entiende bien la intención. |
| Criterios de aceptación | Bien definidos y verificables. | Faltan detalles o pruebas. | Son ambiguos o inexistentes. |
| Valor al usuario | Aporta valor real y medible. | Aporta poco valor o técnico. | No refleja beneficio alguno. |
| Formato | Sigue el formato “Como…, quiero…, para…”. | Formato incompleto. | No usa el formato correcto. |
